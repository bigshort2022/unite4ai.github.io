# Governance

Rules live in this file. Changing them requires a pull request with public discussion —
including for maintainers.

## The ladder

| Role | How you get there | What you can do |
|---|---|---|
| **Learner** | Use the site | Everything public. No account, no data collected. |
| **Contributor** | 1 merged PR | Contributor page, vote in community polls |
| **Maintainer** | 5 merged PRs + sponsorship by an existing maintainer | Review and merge in a content area (CODEOWNERS) |
| **Steward** | Elected annually by maintainers | Admin rights, tie-breaking, accountable to a public decision log |

Inactivity: maintainers inactive for 12 months move to emeritus. Nothing personal; the ladder
reflects current stewardship, and returning is a single request.

## Decisions

- **Content** (adding, editing, removing a card or course) — one maintainer approval.
- **Policy** (governance, license allowlist, code of conduct) — public Discussion open at least
  7 days, then maintainer consensus. Stewards break genuine deadlocks and record why.
- **Removal of a contributor** — Code of Conduct process only, never for disagreement.

## Standing commitments

These are load-bearing. Changing any of them requires a 14-day discussion and a supermajority
of maintainers.

1. Everything on this platform stays under an OSI- or CC-approved open license.
2. No user tracking, no advertising, no data sales — under any funding pressure.
3. Decisions affecting contributors happen in public before they happen in private.
4. We publish our real median review time, including when it's embarrassing.
5. If the project ends, the repository stays public and forkable. Nothing is trapped.

## Conflicts of interest

Maintainers employed by an organization must disclose it when reviewing that organization's
submissions, and should prefer to let someone else review.

## Amending this document

Open a pull request against `GOVERNANCE.md`. That is the whole process.
