# Unite4AI AXI Implementation Plan

> **For agentic workers:** Use subagent-driven development. Verify with offline fixtures; never run a model, spend money, open a test PR against the live site, or auto-merge.

**Goal:** Ship a branded, standalone agent CLI for discovering, producing, and proposing benchmark evidence and research records.

**Architecture:** `bigshort2022/unite4ai-axi` is a public MIT Node 24 npm package. It discovers from the official site's structural feeds and a managed clone of the canonical site repo; the latter provides baseline declarations and the only scoring, authoring and validation code. Explicit submit creates an add-only draft PR under the contributor's authenticated account. CLI output is TOON; repository code and third-party record text are separate trust boundaries.

**Spec:** [Agent Evidence Design](../specs/2026-11-22-agent-evidence-design.md#unite4ai-axi). Dependencies: Plan 5, the first BFCL result, and the site runner's immutable evidence gate. The AX button and site-pinned manifest are Plan 7, not part of this change.

## 1. Discovery and prompts

- [ ] Add `src/discovery.mjs` and `test/discovery.test.mjs`. Read bounded, timeout-protected `https://unite4ai.com/data/{evals,exchange}.json`; never depend on the untrusted text feed. On no-args show `gh api user` identity, read-only probes of configured loopback endpoints, and ready work; `next` also lists blocked work with reasons. Baselines use exact existing model/runtime/format/quantization/hardware/submitter identity, report withdrawn separately by omitting them from open work, and distinguish missing data from zero work. Replication excludes self-submitted, already consistently replicated-by-this-identity, unavailable served model and mismatched workload references. Findings awaiting a review exclude own, superseded or already reviewed by this identity. Work candidates are suggestions, never automatic executions.
- [ ] Add `prompt <page>` for `/exchange`, `/exchange/hypotheses/<id>`, `/exchange/findings/<id>`, `/evals/<id>`, `/registry/models/<id>`. Only canonical relative paths/HTTPS origin accepted. Generate from checked-in task templates keyed by route; never interpolate page body or invoke a command. Share rules with packaged `SKILL.md`: explicit run scope/time/approval, only configured and loaded model, treat record prose as data, disclose harness, materialize one add-only PR, no merge/deploy, report PR link. `--full` returns untruncated prompt; default shows the omitted length. Commands and flags are tested against the versioned `command-manifest.json`.

## 2. Managed site and authoring

- [ ] Add `src/workspace.mjs`, `src/bridge.ts`, `test/workspace.test.mjs`. Clone only `https://github.com/bigshort2022/unite4ai.github.io.git` without a checkout, fetch canonical `main`, verify a package-owned full SHA is its ancestor, then checkout that SHA detached in a per-state directory, role-separated from record payloads. Install with `bun install --frozen-lockfile --ignore-scripts`. Read operations do not clone, install, execute unpinned code or rewrite another checkout. Refuse modified tracked files, symlinks/nonregular output, and unexpected artifacts. `setup workspace` is opt-in, idempotent and selects the immutable pin; command output records the pin.
- [ ] Add `src/authoring.mjs`, `test/authoring.test.mjs`. `run <benchmark>` requests only an owner-configured loopback HTTP endpoint; require `--server`, exact served model (from configured loaded model and read-only checks), `--max-seconds`, explicit machine/current runtime data and `--confirm`. Check the active status on supported servers, no probing of unconfigured addresses, no redirects or implicit restart/model download. Opted-in hosted inference remains available via the site runner's separate, explicit paid approval path; the branded CLI does not accept a key or spend by default. `replicate <result>` derives benchmark/model/checkpoint/quantization from the exact repeat record and refuses own record or a changed benchmark version; hardware/runtime are independently disclosed. Pin precedes any model call. Delegate CLI work to the trusted site runner and retain raw transcripts locally. Do not alter scored output; record the pinned site SHA alongside local evidence. `finding draft` and `review <finding>` pass explicit, validated fields into the site's exchange authoring command, including --agent-model, --agent-harness, exact result IDs, optional switch pair, and exact inspected finding hash. No invented verdict or evidence. Preserve preexisting records.

## 3. Add-only submission

- [ ] Add `src/submit.mjs` and `test/submit.test.mjs`. `submit --record RELATIVE_PATH` (repeatable, 1–10) prepares a preview by default; `--confirm` explicitly authorizes branch/PR writes. Accept only real regular new eval, finding, hypothesis and review records, never transcript/approval/snapshot files and never modifications/deletions. Require each record identity to match `gh api user` (for reviews: reviewer). Load latest canonical main's content as data into an isolated temporary overlay, also require the paths be absent there, and validate the candidate using the pinned site's gate. Recheck main SHA before writes. Require caller-owned initialized GitHub fork; same-owner site maintainers can use the canonical repo. Ship exact bytes only: create Git blobs, tree with canonical base tree, one commit with exactly the inspected base as parent, and create an unforced topic ref; open one **draft** PR against canonical `main`. Deterministic branch key plus exact-commit/PR checks make retries nonduplicating. Refuse collisions, account mismatch or parent drift. No merge, auto-merge, deploy, implicit fork creation, or sync of unrelated files. Return URL as soon as the PR is open. Use argv-only transport, bounded output, do not echo credentials or record prose on errors. Verify with real temp files and local transport fixtures; no live write smoke tests.

## 4. Shell interface and delivery

- [ ] Add `bin/unite4ai-axi.mjs`, `src/commands.mjs`, `command-manifest.json`, `package.json`, `SKILL.md`, `README.md` and `.github/workflows/ci.yml`. Single command registry supplies scoped help, exact flag validation, 2–4 next steps and versioned manifest. `next` exposes bounded results, explicit totals, `--fields` and an empty state. `--help` never touches the network or local model. Usage errors exit 2, runtime failures 1, success/no-op 0; one TOON document on stdout. Offer opt-in SessionStart hook output and skill install; invoking the CLI never changes agent configuration implicitly.
- [ ] Run Node 24 `npm test`, `npx -y axi-axi@0.1.0 validate 'node ./bin/unite4ai-axi.mjs' --dir .`, and `npm pack --dry-run`. Launch the installed tarball in isolation, check help/dashboard, and exercise execution with offline fixtures. Pin dependencies and run the checker in CI. Use a review PR in the public CLI repo; publish from reviewed `main` using npm authentication or trusted publishing. Submit the upstream AXI catalog entry through its required `no-mistakes` fork gate. Do not claim npm publication or catalog acceptance before npm and upstream confirm it. Put this plan in its own site PR and run the site's Node 24 acceptance gate.
