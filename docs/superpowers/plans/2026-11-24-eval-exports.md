# Evaluation Export Interoperability Implementation Plan

> **For agentic workers:** Use subagent-driven development. Use an offline build and fixtures. Do not run a model, register a benchmark, upload a file, or open an upstream PR.

**Goal:** Give each published result a stable, lossless aggregate export and an honest Hugging Face submission status.

**Architecture:** Emit per-record static exports and a versioned index from the site's existing Astro collections. A format adapter owns each upstream projection; the evidence sidecar keeps original numeric values, denominators, provenance and the repeat object. Public URLs describe a specific result, never a leaderboard average or transcript download.

**Stack:** Astro static endpoints, TypeScript, existing Zod schema library, Bun YAML (available at build time), Node 24. No new dependencies.

**Implements:** [Reaching agents upstream](../specs/2026-11-22-agent-evidence-design.md#reaching-agents-upstream) after [Plan 7](2026-11-24-ax-task-handoff.md). Targets: [Every Eval Ever aggregate JSON Schema 0.3.0](https://github.com/evaleval/every_eval_ever/blob/09496fc02c6aa64ed696a95109be08bbd2164020/every_eval_ever/schemas/eval.schema.json) and [Hugging Face `.eval_results` YAML](https://github.com/huggingface/hub-docs/blob/2be4979eec528db07ad8cec06514a176fff50066/eval_results.yaml).

## 1. Every Eval Ever adapter

- [ ] Define typed inputs in `apps/web/src/lib/eval-export-types.ts`: a validated `EvalResult` with its file `id`, benchmark definition, optional model display/open-weight metadata and exact HF artifact ID, and public result/sidecar URLs. Keep publication rules in the loader, transformations pure.
- [ ] In `apps/web/src/lib/eee-export.ts`, emit one aggregate JSON record per result. Use `documentation` (only published aggregate data is converted), evaluator relationship `other` (not inferred), original harness, local inference engine or recorded API provider, and exact artifact identity if observed. A local card ID is a fallback identifier, not a verified upstream model. Cite pinned current source URLs; for historical results cite the exact run page instead of borrowing current source/metric definitions. Encode the UTC run day as a stable date-only surrogate for the required epoch field, label that surrogate explicitly, and include the full result ID in the evaluation ID so same-day runs do not collide.
- [ ] For repeat runs emit mean pass@1 and all-runs pass@k separately, in percent, with correct two-sided 95% intervals and sampling parameters. The all-runs metric is **not** conventional at-least-one pass@k; give it a namespaced metric ID. Do not place across-run standard deviation in the schema's per-sample SD slot. Preserve all repeat fields in the protocol's string-valued `additional_details` as JSON, including counts, interval inputs, timing, tokens and optional energy. Preserve measured companions in their original units with no fabricated uncertainty. No `detailed_evaluation_results` or raw samples.
- [ ] Add independent deterministic tests in `apps/web/test/eee-export.test.mjs`: assert exact numbers, units, metric semantics, omitted absent and historical fields, and strict distinction between identity and attribution. Verify emitted aggregate documents with the pinned upstream JSON Schema using Python `jsonschema` as an external acceptance check, not a new repo runtime dependency.

## 2. Hugging Face adapter and extension proposal

- [ ] In `apps/web/src/lib/hf-eval-export.ts` and `apps/web/src/data/hf-eval-bindings.json`, allow a strict, unique binding by `(benchmark, version)` to the reviewed HF benchmark dataset, exact task, and immutable dataset revision. Include method source and check it matches this definition's source digest; a human reviews equivalence of subset, prompt, sampling, scoring, unit and task in the binding PR. Only an exact HF model artifact positively matched to `setup.served_model` can be a destination; hosted runs, historical definitions without method proof, or absent mappings are blocked with machine-readable reasons. Keep bench and model names distinct. Never reuse public GSM8K/BFCL tasks by name alone; the public GSM8K task does not describe Unite4AI's 200-item method.
- [ ] Serialize a supported mapping as a genuine YAML list: `{ dataset: {id, task_id, revision}, value, date, source: {url, name}, notes }`. Keep unregistered tasks out of `.eval_results` rather than inventing IDs, and show every blocked entry in the export index with a lossless receipt. The sidecar carries all repeat fields; a current-schema `source.url` points directly to it. Never fabricate a verification token, HF identity, or proof of independent replication. Add tests in `apps/web/test/hf-eval-export.test.mjs` for YAML round-trip, exact matching, strict bindings, no zero substitution, and group/metric mismatches.
- [ ] Write `docs/exchange/eval-exports.md`: manual import checklists for each upstream, observed limitations and a concrete, namespaced repeat/units proposal for both formats. Installing or submitting elsewhere is not part of this plan; the owner chooses accounts and destinations. Explain why a blocked Hugging Face entry is not uploadable and how to convert it after a reviewed mapping lands.

## 3. Static artifacts and discoverability

- [ ] In `apps/web/src/lib/eval-exports.ts`, load the same public collections as the leaderboard (`evals`, `benchmarks`, `models`); emit deterministic `/data/eval-exports.json` and per-result `/data/eval-exports/<id>/{every-eval-ever.json,evidence.json}` plus optional `.yaml` when justified. Build URLs using the configured site origin/base and real benchmark run anchors. For the evidence sidecar, copy the original `repeat`, `perf`, `cost`, `api`, and evidence hash/count, preserve exact optional fields, omit execution command, notes and arbitrary external evidence URLs, and never read a transcript. Add a neutral explanation to `/evals` and an agent index link. Do not edit generated registry snapshots or source eval records.
- [ ] Exercise built output for a current BFCL repeat result, an old canary result and a measured companion. Assert one row per file, real source and sidecar links, no fake HF YAML, and deterministic output. Run the narrow tests, then `source scripts/agent/activate-node.sh && node scripts/agent/verify.mjs`. Open a site PR and report the gate's JSON and observed upstream validation; do not publish upstream.
